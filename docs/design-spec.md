# VEGAS 章鱼｜设计需求与视觉规范

## 项目定位
- 项目名：VEGAS 章鱼（VEGAS OCTOPUS）
- GitHub 仓库：`MraJJqq/vegas-octopus`
- 独立项目，不与 Vegas 信号系统、回测系统或交易规则代码混放。
- 目标设备：iPad 全屏沉浸式实时交易大屏。

## 核心体验
打造高端、强烈的科幻交易驾驶舱：多品种行情与真实交易数据构成清晰的数据层，多只机械章鱼作为具有生物感的动态主体，在不同市场区域之间游动，并与真实交易事件互动。

## 已确认的视觉方向
- 以用户选择的方案 A 为基础继续设计。
- 参考用户提供的视觉参考图，优先保留强烈的生物感、机械结构与科幻氛围；避免做成普通卡通章鱼。
- 可采用发光材质、复杂触手、机械关节、能量脉冲、粒子和空间纵深，整体强调高级感与视觉冲击。
- 动画可以适度夸张，以形成视觉盛宴，但行情、信号和账户数据仍必须易读。
- 章鱼可以偶尔游进其他行情区域，与各区域产生互动；不要持续遮挡重要数据。
- 多只章鱼可在不同区域间自由游走，抓取代表美元的金币。

## 交易事件与动画规则
- 盈利事件：章鱼抓取金币，表现盈利入账。
- 亏损事件：章鱼吐出金币，表现资金流出。
- 动画必须由真实交易事件、真实盈亏数据或明确标注的模拟事件驱动。
- 不得用虚构动画或虚构数字冒充真实交易结果。
- 没有真实交易事件时，不得暗示账户正在盈利或亏损。

## 数据展示范围
1. 多品种行情：为美股、BTC、HYPE、黄金、原油等市场预留可扩展接口。
2. Vegas 信号：展示上游系统输出的信号，不在本项目内擅自修改交易规则。
3. 交易记录：展示真实交易事件、方向、价格、盈亏及状态。
4. 账户资金：展示资金、持仓、盈亏和收益曲线。
5. 连接状态：清楚区分实时、延迟、断开、缺失和模拟数据。

## 架构与安全边界
- 前端视觉层与行情/交易数据适配层分离。
- 本项目初期只做监控与可视化；未经明确授权，不接入自动下单。
- 不改变现有 Vegas 交易规则。
- API 密钥、令牌和账户凭证不得提交到 Git；应通过环境变量或安全密钥管理配置。
- 数据过期或接口失败时必须显式提示，不能继续伪装成实时行情。

## 开发顺序
1. 确认大屏分区与方案 A 的最终布局。
2. 搭建可运行的前端骨架与响应式全屏画布。
3. 建立行情、信号、交易事件和账户数据模型。
4. 接入并验证真实行情来源。
5. 实现章鱼游动、触手与金币动画。
6. 将真实盈亏事件映射到抓取/吐出金币动作。
7. 验证数据准确性、连接状态、性能和遮挡情况。

## 当前状态
项目处于初始化与设计整理阶段。当前文档记录已确认的方向；尚未表示行情、账户或交易接口已经接通。用户提供的原始参考图片仍以原对话附件为准，本文件记录其视觉方向，不声称已复制原图文件。
